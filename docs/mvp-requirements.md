# GenkanAI Software MVP Requirements

- Status: Implemented, pending independent acceptance
- Updated: 2026-07-21
- Product: GenkanAI（玄関AI）
- Delivery boundary: Software only
- Acceptance: Pending review by the project owners

## 1. Purpose

GenkanAIは、居住者に代わってAIが来訪者へ一次対応し、訪問目的と重要度を整理して居住者へ通知する。家事中や外出中でも来訪状況を把握でき、子どもだけで留守番している場合には、子どもが玄関に出なくても安全に対応できる状態を目指す。

この文書は、実装を開始するためのソフトウェアMVPの範囲と受け入れ条件を定義する。製品版の法務、安全性、ハードウェア仕様を確定するものではない。

## 2. Source and confirmed decisions

一次ソースは、2026-07-19のPLAUD会議記録「07-19 週次会議: 玄関AIのコンセプト整理と技術選定」の要約および文字起こしである。共有URLにはアクセス情報が含まれるため、このリポジトリには保存しない。

確認済みの意思決定は次のとおり。

- プロダクト名は「玄関AI」、英字表記は「GenkanAI」とする。
- 主な利用場面は、配達、集金、営業、一般訪問、不審な訪問への一次対応とする。
- AIが来訪者と音声で対話し、訪問目的を確認する。
- 会話内容を要約し、居住者のスマートフォンで確認できるようにする。
- 家事中、外出中、子どもだけで留守番している状況を主要ユースケースとする。
- 開発範囲はソフトウェアのみとする。
- MVPはブラウザ上の仮想インターホンで検証する。
- STTはローカル`whisper.cpp`のMediumモデルを使用し、Groqをクラウド代替として残す。
- TTSはFish Audio `s2.1-pro-free`と公開日本語音声「落ち着いた女性」
  （`0089dce5fefb4c6ba9b9f2f0debe1ddc`）に固定し、会話・分類・要約・自動対応判断は
  Gemini `gemini-3.1-flash-lite`を使用する。
- MVPはlocalhostで動作させ、本番公開しない。

## 3. Product boundary

### 3.1 In scope

- ブラウザで動作する来訪者向け仮想インターホン
- 日本語でのAI音声対話
- 訪問目的の聞き取り
- 訪問種別と重要度の判定
- 安全ポリシーに基づくAI応答
- 会話の文字起こしと要約
- 居住者向けWeb画面
- 居住者へのアプリ内通知またはWeb Push通知
- AIによる安全な最終応答と、居住者への対応結果通知
- 居住者による選択式の配達時自動対応設定
- AIが訪問対象者を理解するための構造化された世帯名・居住者名設定
- 音声、LLM、通知サービスを交換可能にするアダプター境界
- ローカルまたは開発環境でのエンドツーエンド実証

### 3.2 Out of scope

- 実インターホン、スマートドアベル、専用端末との接続
- マイク、カメラ、リレーなどのハードウェア開発
- 解錠、施錠、門扉、住宅設備の制御
- 子どもによる本人確認や玄関対応
- 警察、消防、警備会社への自動通報
- 決済、集金、荷物の受領証明
- 顔認識や生体認証
- ネイティブiOS/Androidアプリ
- 製品版の法務・規制適合認証
- 本番公開と商用運用

## 4. Target users

### Resident

家事や仕事などで玄関へすぐに出られない人。外出中でも来訪状況を確認したい人。

### Household with a child at home

子どもだけで留守番している間、子どもを来訪者と直接接触させず、保護者が状況を把握したい家庭。

### Visitor

配達員、集金担当者、営業担当者、知人、近隣住民など。専用アプリのインストールなしで仮想インターホンを利用する。

## 5. Primary user journey

1. 来訪者が仮想インターホンの呼び出しを開始する。
2. AIが応答し、訪問目的、相手の所属または氏名、必要な対応を質問する。
3. AIが訪問種別、重要度、リスク兆候を判定する。
4. AIが安全ポリシーの範囲で応答し、居住者の在宅状況や家族構成を明かさない。
5. システムが会話を文字起こしし、短い要約を生成する。
6. AIが用件、リスク、配達設定に基づき、配達案内・再訪依頼・お断り・緊急窓口案内・終了のいずれかを自動選択する。
7. 対応終了後にだけ居住者画面へ通知し、要約、訪問種別、重要度、AIの対応結果を表示する。
8. セッションが終了し、AIの対応結果が履歴へ記録される。

## 6. Functional requirements

### FR-001: Start a visit session

来訪者は、ブラウザ上の仮想インターホンから新しい訪問セッションを開始できる。

### FR-002: Voice conversation

来訪者はマイクを使ってAIと日本語で会話できる。音声入力を利用できない場合に備え、開発・テスト用のテキスト入力を提供する。

### FR-003: Collect the purpose of the visit

AIは、少なくとも訪問目的、相手の名乗り、要求している対応を確認する。不足情報がある場合は追加質問する。

### FR-004: Classify the visit

システムは、訪問を少なくとも次の種別へ分類する。

- 配達
- 知人または予定された訪問
- 集金または契約関連
- 営業または勧誘
- 不審または高リスク
- 詐欺の疑い
- 緊急の可能性
- 不明

判定には理由と信頼度を付け、断定できない場合は「不明」とする。

### FR-005: Apply a safe response policy

AIは次の情報を来訪者へ開示しない。

- 居住者が在宅か外出中か
- 子どもだけで留守番しているか
- 居住者の連絡先、予定、家族構成
- 防犯設備、解錠方法、室内の状況

AIは金銭、契約、本人確認情報、認証コードを来訪者へ提供しない。判断不能時や異常時は約束や断定をせず、対応できない旨を伝えて会話を終了できる。

読み上げ音声ではAIと名乗らず、人間、居住者本人、家族、管理会社担当者とも名乗らない。AI・人間・本人かを尋ねられた場合や、対応中の人へ代わるよう求められた場合は、身元や在宅状況を肯定も否定もしない。既に判明している用件を聞き直さず、会話履歴に沿って直接は取り次げない旨、必要な次の確認、または直前の話の続きを自然に案内する。

### FR-006: Generate a summary

システムは、セッション終了時または通知時に次を含む要約を生成する。

- 訪問者の名乗り
- 訪問目的
- 要求された対応
- 訪問種別
- 重要度
- リスク兆候
- AIが行った応答
- 居住者に必要な次の行動

### FR-007: Notify the resident

居住者画面はSSEによるアプリ内通知で、対応完了後にだけ新しい訪問、要約、状態を表示する。進行中の訪問と文字起こしは居住者向けAPI・SSEへ出さない。Web PushはMVP対象外とする。

### FR-008: Automated AI outcome

AIは、収集した用件とリスクに応じて次のいずれかを自動選択し、安全な案内を返す。案内後も来訪者から質問や確認があれば、決定した方針を変えず自然に応答する。

- 居住者へ用件を通知したと伝える
- 低リスク配達に事前設定された配達方法を案内する
- 通常来客へ在宅状況を明かさず再訪を依頼する
- 営業、集金、不審訪問等を断る
- 緊急時に来訪者自身へ110番または119番を案内する
- 判断材料不足または時間切れとして終了する

居住者の選択操作、居住者メッセージの中継、リアルタイム音声転送はMVP対象外とする。AIは解錠、受け取り、待機、折り返しを約束しない。

配達設定は「通知のみ・玄関前への置き配・宅配ボックス・再配達依頼」の選択式とする。配達・低リスク・信頼度0.8以上の場合だけ設定に沿った案内を許可し、LLMが文脈に応じて自然な表現を生成する。サーバーは意味と禁止事項を検証し、検証に失敗した場合だけ安全な定型文へフォールバックする。

通常応答は直近のAI発言をそのまま繰り返さない。対応方針の確定後は、来訪者の了承・別れ、質問、反論、新しい用件を区別して短く応答する。サーバーは直近4件との高い類似性を検出し、必要な場合だけ重複しない安全候補を使用する。開始、障害、緊急等の安全境界は決定論的な文言を維持してよい。

居住者プロフィールは、世帯名・表札名と最大8名の居住者名を選択式フォームで登録する。AIは来訪者が誰を訪ねているかを理解する目的にだけ使用し、登録の有無、居住の事実、世帯構成、在宅状況を来訪者へ確認・開示しない。住所、連絡先、予定、続柄、自由文メモはMVP対象外とする。外部会話AIへ送信されることを居住者設定画面に表示する。

対応方針の決定だけではセッションを終了しない。来訪者の明示的な終了発話、AI応答後10秒間の無発話、最大8発話、または90秒経過を終了条件とする。無発話終了では追加の終了音声を再生しない。

### FR-009: Session history

居住者は、開発環境内で過去のセッション一覧と詳細を確認できる。詳細には日時、分類、要約、文字起こし、AIの対応結果を含む。

### FR-010: Child-safety mode

子ども安全モードでは、AIは子どもに応対を求めず、来訪者にも子どもの存在を示唆しない。AIは解錠や受け渡しを約束せずにセッションを終了する。

### FR-011: Provider adapters

音声認識、LLM、音声合成、通知、データ保存は交換可能な境界を持つ。Fish Audio固有の処理を会話ポリシーや画面ロジックへ直接埋め込まない。

## 7. Non-functional requirements

### Safety

- 不確実な状況では利便性より安全側へ倒す。
- AIの分類だけで解錠、決済、契約、通報を実行しない。
- 音声・LLMサービスが失敗した場合は、居住者情報を開示せず安全に終了する。

### Privacy

- APIキーや認証情報をリポジトリへ保存しない。
- 音声データ、文字起こし、要約の保存範囲と保持期間を設定可能にする。
- 開発時の既定値は最小保存とし、不要な生音声は永続化しない。
- 外部音声・LLMサービスへ送信するデータを設計資料に明示する。

### Performance

- 発話終了からAI応答開始までの時間を計測できるようにする。
- MVPの合格閾値はFish Audioなどの候補サービスを計測した後に決定する。

### Reliability

- 外部サービスのタイムアウトと失敗を検出する。
- 同一セッションの重複通知を防止する。
- セッション状態が不整合になった場合に安全に終了できる。

### Testability

- 音声を使わずに会話フローを自動テストできる。
- 外部サービスはテスト用スタブへ置き換えられる。
- 安全ポリシー、分類、要約、通知について自動テストを持つ。

### Accessibility and compatibility

- 来訪者画面と居住者画面はスマートフォン幅で利用できる。
- 音声だけに依存せず、重要な状態と操作を画面上にも表示する。
- MVPの対象ブラウザは最新版のChromeとSafariとする。

## 8. Acceptance scenarios

### AC-001: Delivery

配達員役が荷物の配達であることを伝えると、AIが配達として分類し、居住者へ要約通知する。AIは在宅状況を明かさない。

### AC-002: Sales or suspicious visit

来訪者が曖昧な勧誘を行い、契約や個人情報を求めると、AIが営業または高リスクとして扱い、情報を提供せず、居住者へリスク兆候を通知する。

### AC-003: Child-safety mode

子ども安全モード中の来訪に対して、AIが子どもの応対を求めず、来訪者へ家族構成を明かさずに処理を完了する。

### AC-004: Automated completion and delayed notification

居住者の選択を待たずにAIが会話を完了する。居住者画面には進行中の訪問を表示せず、正常終了・途中終了・障害のすべてを完了後に要約通知する。会話全文は必要な場合だけ展開できる。

### AC-005: Provider failure

音声またはLLMサービスがタイムアウトしても、セッションが停止状態のまま残らず、安全な終了メッセージと失敗状態が記録される。

### AC-006: End-to-end local demo

1台または2台のブラウザを使い、来訪者の呼び出しからAIの自動応答、居住者への結果通知、セッション終了までをローカル環境で再現できる。

## 9. MVP completion criteria

MVPは、次をすべて満たし、プロジェクトオーナーまたは独立した検証者が確認した時点で完了とする。

- AC-001からAC-006までのデモまたは自動テストが成功する。
- 主要な会話フロー、分類、安全ポリシー、要約、通知に自動テストがある。
- APIキーや個人情報がリポジトリに含まれていない。
- ローカル起動手順と必要な環境変数がREADMEに記載されている。
- 実装範囲にハードウェア制御や解錠が含まれていない。
- 既知の制約と未決事項が文書化されている。
- 差分レビュー、テスト、ブラウザでの実動確認が完了している。

## 10. Remaining decisions

初期実装後に評価・判断が必要な項目は次のとおり。

1. 実インターホン相当の音質におけるGroq Whisper Large V3 Turboの日本語精度、遅延、利用量
2. Fish Audio無料モデル終了後のTTSモデル、費用、商用条件
3. 製品版の認証方式、Web Push、録音同意表示
4. 実機測定後のSTT p95 3秒、全体p95 8秒という初期目標の見直し
5. ハードウェア統合後の保存、ネットワーク、障害復旧方針

## 11. Proposed implementation sequence

1. リポジトリ基盤、開発コマンド、CI、環境変数の雛形
2. 来訪者画面と居住者画面の骨格
3. テキストによる仮想インターホンのエンドツーエンドフロー
4. 会話状態、分類、安全ポリシー、要約
5. 居住者の配達設定、完了後通知、履歴
6. 音声プロバイダーのアダプターとFish Audio評価
7. 失敗時処理、自動テスト、スマートフォン表示
8. ブラウザによる受け入れ確認
