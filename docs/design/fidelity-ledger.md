# UI fidelity ledger

実施日: 2026-07-22

この記録は実装者による UI QA であり、受入判定ではない。最終受入は別の Codex 実行または Core / 琉伊によるレビューで行う。

## Build Week virtual intercom

### Design specification

- Primary experience: 来訪者が画面上の物理インターホンを押し、通常の玄関と同じ感覚で会話する。
- Visual hierarchy: インターホン本体、状態表示、呼び出しボタンを主役とし、開発情報はプレゼンターパネルへ分離する。
- Typography: macOS / iOS のシステム日本語書体を使い、端末表示だけ大きく太くする。
- Color: 建材の黒・チャコールを基調に、音声状態は緑、呼び出し操作は暖色アンバーで示す。
- Components: 端末ディスプレイ、波形、スピーカー孔、状態灯、呼び出しボタン、デモ情報、居住者画面リンク、プレゼンターパネル。
- Responsive: デスクトップは端末と右ドロワー、390px幅では端末を一画面に収め、ドロワーを全幅表示する。

### Fidelity comparison

| 観点 | 設計案 | 実装結果 | 判定 |
| --- | --- | --- | --- |
| 主役 | 建材壁面に物理インターホンを単体配置 | 通常のアプリナビを隠し、端末を中央へ配置 | 一致 |
| 端末構造 | 画面、波形、スピーカー孔、状態灯、大型ボタン、マイク孔 | すべてCSSとアイコンで再現 | 一致 |
| 状態表現 | 緑の波形・状態灯、アンバーの呼び出しリング | 会話フェーズに応じて波形、灯、ボタン状態を切り替え | 一致 |
| プレゼン情報 | 右側に処理パイプラインと会話ログ | 4段階パイプライン、会話ログ、シナリオ、代替入力を格納 | 一致 |
| 情報分離 | 来訪者体験には技術名を出さない | 初期画面では技術情報を非表示、`デモ情報`でのみ展開 | 一致 |
| デスクトップ配置 | 端末と右ドロワーを並置 | 1440px幅で重ならず表示 | 一致 |
| モバイル配置 | 端末を画面内に収める | 390 × 844で横スクロールなし、主要操作とフッターを表示 | 一致 |

| 端末アイコン | コンセプトはマイク | 実装は呼び出しベル、通話中は波形 | 意図的差分 |

### Above-the-fold copy diff

- Concept: `お話しください` / `呼び出す` / `プレゼンターモード`。
- Runtime waiting state: `呼び出してください` / `待機中` / `呼び出す`。
- Runtime active state: `お話しください` / `通話中`。
- Waiting stateだけ操作を明確にするため `呼び出してください` とし、通話開始後はコンセプトどおり `お話しください` に切り替える。

### Browser QA evidence

- デスクトップで `呼び出す` を押し、宅配シナリオをテキスト代替入力から送信した。
- 来訪者画面が `ありがとうございました` / `通話終了` へ遷移し、会話ログに開始応答、来訪者発話、最終応答が1件ずつ表示された。
- 居住者画面に山田運輸、配達、低リスク、要約、適用した配達方針、次の行動、通知済み状態が表示された。
- 1440 × 1000と390 × 844の両方でconsole error/warnは0件だった。
- 390 × 844で `scrollWidth === clientWidth === 390` を確認した。

### Remaining visual risk

- コンセプト画像の金属・壁面テクスチャは生成画像ほど写実的ではなく、CSSグラデーションで近似している。
- 実マイク権限と音声プロバイダーを使った表示遷移は、このUI QAではなく既存の音声MVP検証に依存する。
